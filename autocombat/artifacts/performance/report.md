# 模拟与锦标赛加速验证

2026-11-15，在本机 Windows、Python 3.14、20 个逻辑处理器上，以修改前源码副本 `baseline/` 与新版分别运行。保持角色、权重、地图、赛季状态和战斗规则；吞吐量测试使用 8 个进程。结果为单次端到端测量，包含启动开销，并非所有配置的速度保证。

| 场景 | 原版 | 新版 | 速度提升 |
|---|---:|---:|---:|
| 命令行两队 2v2，400 场 | 40.94 秒 | 12.29 秒 | 3.33 倍 |
| 多轮预赛入口，三种赛制，1 轮，1v1 目标场数 30 | 35.32 秒 | 9.72 秒 | 3.64 倍 |
| 网页锦标赛，12 队，492 场预赛 | 81.05 秒 | 29.61 秒 | 2.74 倍 |
| 命令行 verbose 单场，新版开启 `--fast` | 12.16 秒 | 2.70 秒 | 4.51 倍 |
| 网页 verbose 单场，新版开启极速 | 7.19 秒 | 1.58 秒 | 4.55 倍 |

新版批量单进程耗时 41.08 秒，收益主要来自多核并行。verbose 的上述提升包含取消播放等待，不代表单场战斗计算本身加速 4.51 倍。短任务可能受进程启动成本影响，预赛会按场数限制工作进程，多轮之间复用进程池。

网页 verbose 原版与新版均返回 273 条日志和相同的四回合战果；其收益主要来自批量日志传输与减少状态落盘，原版本身没有逐回合播放等待。该测量使用临时赛事数据、空 AI 权重，与命令行场景分别测量。原始结果见 `verbose_web.json`，测量脚本为 `verbose_web_benchmark.py`（传入源码目录）。

## 实现与兼容

- 两队批量对战与预赛使用隔离进程；锦标赛复用多个独立赛事工作进程，按赛程顺序计分并生成季后赛。
- 支持 `--workers 1–32`；命令行 verbose 使用 `--fast`，网页 verbose 与锦标赛逐回合模式提供极速开关。网页设置仍支持原有速度控制和暂停。
- 完整 verbose 日志保留，极速模式批量传输；状态最多每秒保存一次，结束时立即保存。常驻工作进程切换请求时重新绑定日志缓冲。
- Windows 取消模拟会清理子进程树；非 Windows 使用独立进程组。进程异常向上报告，不静默跳过预赛比赛。
- 子进程使用固定任务数据、设置和权重，避免共写日志文件。每场独立种子和稳定的子进程哈希种子用于跨并发数复现。
- 新旧版随机数分配方式不同，不承诺相同种子的逐场结果或最终排名与旧版相同。没有减少比赛、修改 AI 决策规则或降低回合上限。
- 已有赛事保留其战斗源码和权重快照；更新传输适配层。更新代码后需要重启后端。

## 验证记录

前端 `npm run build` 通过，包括 TypeScript 检查和 Vite 生产构建。Python 语法及改动文件空白检查通过。

新增真实进程回归覆盖：两队批量跨进程数与 CLI/Web 统计一致；全部赛制预赛跨进程数一致及 CLI 入口；普通与极速 verbose 日志一致、常驻进程连续请求不丢失战斗日志；真实锦标赛预赛的计分、完成状态、季后赛生成和进程清理。

原有网页测试中的三处失败在修改前副本中同样复现：角色启用校验一处、直接与逐回合回放的回合数断言各一处。保留这些既有失败，不修改用户的角色和平衡性改动来使断言通过。

最终测试结果见 `checks.json`、`test_acceleration.log`、`test_sim_prelim.log`、`test_uiall.log` 和 `test_settings.log`。原始耗时见 `benchmark.json` 与 `modes.json`。

最终汇总：新增加速回归 4/4、命令行预赛 19/19、设置 10/10、网页相关测试 53/56；合计 86 项通过，剩余三处为上述已复现的既有失败。

## 复现

```powershell
python artifacts/performance/benchmark.py
python artifacts/performance/benchmark_modes.py
python artifacts/performance/verify.py
cd frontend
npm run build
```

`baseline/` 是实施前工作区源码和权重副本，包含用户当时未提交的改动；不是从 Git HEAD 重新导出的版本。基准脚本会更新本目录中的测量日志。
