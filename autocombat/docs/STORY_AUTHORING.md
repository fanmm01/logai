# 剧情创作

从首页或侧栏进入“剧情模式”，再打开“创作工作区”。默认示例位于仓库的 `story-projects/demo/`；可以打开任意服务端创作目录。开发阶段剧情创作接口对所有已建立会话的访问者开放。

工作区顶部可直接选择故事，列表包含 `story-projects/` 下的故事及此前打开的目录。点击“新建故事”，输入名称后“创建并打开”，会自动生成项目配置、序章流程和占位正文。切换有未保存草稿的工作区时会提示确认；需要保留修改时先点击“全部保存”。

源码是唯一内容来源。`.flow` 负责流程，`.txt` 负责剧情，`.chos` 负责返回选项，`.gmf` 负责游戏，`.rule` 声明执行协议。流程图修改回写文本，拖动只改变 `.story-editor.json` 中的坐标；“总流程图”查看章节接续，点击章节进入该文件。Ctrl+S 保存全部草稿。点击文件树中的媒体可在当前源码位置插入引用。编辑器接受 CRLF／LF，保存时统一为 LF。

“预览草稿”使用独立项目与进度；“发布”生成不可变版本，旧运行和存档继续使用原版本。应用内切换页面保留创作草稿，关闭有未保存修改的页面时会提醒。

手机和窄屏默认进入源码模式，文件列表折叠到左上角“文件”按钮，选择文件后自动收起。并排模式单击内容节点会在旁边打开对应文本，并保留当前流程图；其他模式双击内容节点可直接打开文件。节点属性仍编辑流程语句本身。

阅读剧情时舞台自动铺满浏览器视口，竖屏保持原方向，小横屏也不强制旋转。右上角可进入浏览器全屏；剧情选择和“确认阵容”同处舞台图层。存档、读档、历史、阅读设置和暂停收在“菜单”中，底部不再放置重复控件。点击未展示完的文字会立即补全，再次点击推进下一段；切段加载期间最多保留一次推进输入。

## 入口与接续

```text
@START:
->chapter1
->END
```

多入口使用逻辑“或”，文件头末尾冒号可省略：

```text
@XU.CONTINUE-A||@SC1.CONTINUE-AR||START
```

只含 CONTINUE 的文件需要前章对应结算记录。含 START 的文件也可独立开始；多个入口可用时由玩家选择“重新开始”或具体接续来源。CONTINUE 继承变量、计数和媒体，不混合不同来源记录。

同一来源章节与 CONTINUE 标签只显示一个接续入口，重复完成前章会更新为最近一次完成的状态。不同来源或不同标签仍是独立入口，已经开始的运行和已保存的存档不受更新影响。

`MAIN` 只写默认起点名，例如 `XU`。调用者也可明确选择起点。

## 自然剧情

```text
\m starlight.wav
\bg courtyard.svg
\mem 春晌，葬火,知夏
春晌：庭院里，风翻开了信。
“如果是你的话……”
她想了一会。\
“可以，帮我吗？”
：这一块强制旁白。
\“这里的引号不表示对话。”
\b黑屏文字。
下一段仍为黑屏文字。
b\
普通文字。
```

缩进不参与语义。具名冒号设置说话人，空名字冒号强制旁白。行尾单个反斜杠连接下一行，同一语块中任意行以未转义左引号开头，整个语块判为当前人物的对话；强制旁白优先。

`\mem` 接受中文、英文逗号及混用，最多五人，顺序从左到右；空名称、重复、未知角色和六人以上均报错。角色名在 `story.project.json` 的 `figures` 中映射到 `figure/` 资源。空参数或 NONE 清场。每次指定完整可见集合。

音乐和背景默认延续；`\m` 或 `\m NONE` 停音乐，`\bg NONE` 清背景。资源分别放在 `bgm/`、`background/`、`figure/`、`vocal/`、`animation/`。前台视频可以放根目录或 `video/`。

`\b` 开启黑屏文字，后续语块持续使用黑屏，直到行首的 `b\` 结束。`mem\` 清除立绘，`bg\` 清除背景，`m\` 停止音乐；各状态独立持续，新的资源指令可直接替换当前资源。结束标识可单独成行，也可连续写成 `b\mem\bg\m\`，后面可接普通正文。

已知 WebGAL 指令可直接书写，如 `setTransform`、`setAnimation`、`playEffect`。整份原生脚本可用 `#!webgal` 首行声明。原生场景调用在当前运行版本内加载；复杂原生脚本使用原生 choose/label/callScene 语法。

## 选择与权限

```text
\c{
    __LOCK 1“去灯塔”;  // 初始锁定，不显示标记
    2“留在庭院”;
}
\c1 ：灯塔路线。
\c2 ：庭院路线。
\c
：公共后文。
```

`.txt` 的选择在文件内汇合；`.chos` 的顶层选择在正文和公共后文执行完后返回数字编号。允许没有分支正文，或省略末尾 `\c`。编号必须为数字，不能重复。

```text
UNLOCK@MC2
LOCK@MC2
UNLOCK@crossroads[1]
LOCK@crossroads.chos[2]
```

可以在 flow、自然正文或选项正文中执行。编号是声明的编号，非屏幕下标。标记保存于玩家项目档案；重试、重启、读取旧档不会回滚。后执行的显式指令优先于初始 `__LOCK`，打开选项不会重新上锁。

LOCK 不驱逐正在播放的章节；它阻止后续新进入。UNLOCK 不生成接续状态：只有 CONTINUE 的文件仍须有前章记录；含 START 的混合入口可独立开始。显式 LOCK 不被自动接续解锁覆盖。锁定选项显示但禁用，原生条件仍生效；所有项锁定时可读档或返回。

## 流程

```text
@START:
->dialog1 <again
->crossroads{
1: mark=1;
   ->battle{'w':->;'l':->RETRY;}
2: ->(time(again)<3)?again:ending;
}
->ending <ending
->END
```

省略扩展名按 txt、chos、gmf 查找；别名优先于文件。`->;` 退出当前分支，正常结束也汇合。if/else、赋值、三元跳转、算术、比较和逻辑表达式使用独立解释器，不执行 Python/JavaScript。time 返回带标签节点的进入次数，首次为 1。

RETRY 返回最近游戏块或选择源，保留变量、计数和玩家权限，重建该入口的媒体与游戏状态。失败重试先提示。读取存档则恢复当时的变量、计数和随机序列，但不撤销项目档案中的显式权限变化。

## AUTOCOMBAT

```text
rule AUTOCOMBAT
set TEAMS:Y{Y5,Y60,Y7,Y8},X{Y9},Z{Y12};
set CONTROL:NONE;
set BIND:Y;
set CARRY:FULL;
set CARRY_FIELDS:cooldowns=false;
battle Y vs X KEEP_STATUS;
battle Y vs Z;
if (isAlive(Y)) return "w";
else return "l";
DISPLAY:AUTOCOMBAT_DEFAULT
```

KEEP_STATUS 控制本场到下一场的继承。FULL 保留全部；RESOURCES 保留 HP/MP/SAN、死亡及库存；NONE 使用初始基线。可覆盖 resources、statuses、cooldowns、inventory、summons、usage。CONTROL:NONE 全部 AI，BIND 只指定视角；CONTROL 也可列出手动队伍名。

新波重建行动和先攻，不额外恢复资源，不重复施放保留队伍的入场被动。达到游戏块后先显示双方卡片及技能，再进入原有战术室。战斗可暂停、单步、调速、存档；重启恢复后默认暂停。
