# 星序 · 浏览器战术室

## 页面宣传文案

页面宣传语统一维护在 `src/data/pageCopy.json`，按页面分组：`home`（首页）、`setup`（作战准备）、`library`（图鉴）、`battle`（对战）、`settings`（设置）、`storyChapters`（章节选择）、`storyEditor`（创作室）、`storyPlayer`（剧情播放）。中文宣传语和英文装饰标题均在此修改；数组中的每一项对应一行文字。保留字段名，只修改文字内容。修改后运行 `npm run build:app`，刷新页面即可。角色技能说明仍维护在 `src/data/encyclopedia.json`。

明亮卡牌风的 autocombat 界面，连接原有 CoC 战斗引擎。角色图鉴自动读取当前角色数据，不要求角色立绘。

## 启动

在项目根目录运行：

```powershell
python -m pip install -r requirements.txt
python start_ui.py
```

浏览器访问 `http://127.0.0.1:8889/ui/`。HTTP 服务默认监听 `0.0.0.0:8889`，另有 `0.0.0.0:8892` TCP 字节流转发入口；TCP 隧道映射本机 8892 后，浏览器通过隧道提供的 HTTP 地址访问 `/ui/`。用 `python start_ui.py --tcp-port 8893` 可更改转发端口。首次构建需要 Node.js 20.19+ 或 22.12+ 以及 npm；之后 Python 服务提供构建后的静态文件，无需常驻 Node 服务。

局域网多人使用无需额外参数，直接运行：

```powershell
python start_ui.py
```

好友须通过 `http://房主局域网IP:8889/ui/` 打开页面，然后输入房间码。创建时选择“局域网房间”，分配角色、等待玩家准备后开始；也可作为观众加入。若系统防火墙阻止连接，请由使用者按自己的网络设置允许该服务。

手动构建与原入口兼容：

```powershell
cd frontend
npm ci
npm run build
cd ..
python scripts/merge_backend.py
python backend/autocombat_backend.py --host 127.0.0.1 --port 8889
```

开发时先启动 Python 后端（8889），再在 frontend 运行 `npm run dev`。代理会转发 `/api` 并设置同源 Origin；界面默认路径为 `/ui/`。正常使用推荐 Python 同源入口。

## 功能

- 大厅、编队、角色图鉴，内置角色 SVG 徽记与可替换卡面。
- 本地控制双方；每角色可选择 AI；自由对战中可在参战阵容勾选／取消“AI”，随时转交或接管角色（召唤物按组切换）；支持双方同编号的镜像对局。
- 局域网房间、房主分配、玩家准备、观众权限、离开后房主接管。
- 棋盘与先攻顺序、主／附动作、MP／SAN、领域、状态、物品、召唤组与墓地。
- 技能目标与移动范围提示；确认前运行隔离副本预览，保留真实资源与随机状态。
- 待反应状态可刷新恢复，后续效果继续由原引擎处理。
- AI 播放、暂停、单步、1×／2×／4×；事件时间线与战后回顾。
- 独立子进程批量模拟，含种子、场数、赛季状态、结构化进度与 CSV／JSON 导出。
- 浏览器刷新及 SSE 断线恢复；重复请求去重、过期版本拒绝、房间身份验证。

## 交互

1. 编队后创建演习，在准备阶段选择己方角色，可调整站位。
2. 开始后点击技能，再点击高亮目标；也可选择“使用默认目标”。
3. 移动时高亮可达格；点击后确认。非法行动不会扣动作。
4. 受到攻击时用反应面板选择闪避、反击或格挡；不可用的方式不会出现。
5. 复活技能从“墓地”页选择合法对象。召唤组可在左侧选择成员展开查看。
6. 左侧角色用于选中与指定目标；底部操作始终属于当前行动角色。
7. 时间线查看历史时禁止提交战斗动作；点击“回到实时”恢复。

## 自定义美术

技能百科文案模板统一维护于 `src/data/encyclopedia.json`，由 `src/encyclopedia.ts` 按角色编号、技能名和阶段匹配。技能费用、伤害、范围、召唤物、制造物及专属规则通过显式引用读取 `/api/ui/catalog` 返回的角色 data，在载入目录时统一解析，正文、预览和术语释义共用解析后的结果。数值平衡只需修改 `../characters_data.py` 并重载后端；百科不再维护第二份数值。修改文案模板后运行 `npm run build`，刷新页面即可。新增技能或阶段缺少条目时会明确显示尚未编写；缺失数据字段显示“未配置”。`../character_encyclopedia.py` 仅保留为旧版文案和机制测试兼容资料，不再参与页面运行。

引用示例：`{{spell.effects.0.伤害骰}}`、`{{character.passive_rules.frost.dot}}`、`{{summons.玄武.HP}}`、`{{items.蛋糕HP.回复hp}}`。跨技能使用名称（如 `{{skills.幻造兵武.effects.0.辅助效果值}}`），召唤物攻击与法术分别使用 `summonSkills.朱雀.爪击`、`summonSpells.朱雀.俯冲`，避免技能排序改变后错配。多段攻击使用 `{{spell.effects.*.伤害骰|join:、}}`。比例用 `|percent`，符号用 `|signed`，命名属性修正用 `|modifier:行动力`；这些只负责格式化已明确指定的字段，不会按上下文猜测和替换数字。固定机制常量（例如 D100、八层循环与每次事件的次数）保留在说明中。

运行 `npm test` 校验引用路径、技能身份与修改 data 后的联动；运行 `npm run test:browser` 检查桌面和移动布局。小雪人的近战参数位于 `SUMMON_TEMPLATES['小雪人']['frost_melee']`，引擎和百科共用。

帮助中的公共机制维护于 `../docs/游戏总机制.md`。保留八个 `##` 分类的顺序以兼容机制链接，每个 `###` 条目用 ` / ` 分隔同义术语，条目下的全部正文同时用于帮助页与角色卡释义，不再按关键词截取句子。帮助可搜索正文、别名、角色名与编号；专属机制索引读取已解析的角色百科，随当前角色数据更新。新增术语应补在相应条目标题中，专属资源与状态通过 `src/knowledge.ts` 的角色术语及简称映射关联。

角色专属被动参数维护在 `../characters_data.py` 各角色的 `passive_rules` 中；冰冻循环、卡带资源、火鼠裘、写作收益和月能门槛不再散落在引擎计算中。血术月相表归入夜诏明的 `blood_rules.moon_phases`，初始武器使用 `initial_weapon`。这是数据归位，不是一次数值平衡调整。

18 个角色徽记与 106 个技能 SVG 资源位于 `public/icons/`，可用 `python scripts/generate_library_icons.py`（在项目根目录执行）重新生成。新增角色时先补充资料和徽记路径；改动源码后重新构建前端，改动引擎后运行 `python scripts/merge_backend.py`，重启服务以载入新的 Python 模块。

在 `public/portraits/` 放置 `Y1.webp` 等竖版图片、`Y1-avatar.webp` 等头像，再重新构建。没有图片时使用统一配色的徽记。推荐 3:4 竖版立绘与方形头像。界面设置可关闭动效。

## 边界与运行说明

普通战斗房间和时间线保存在内存，服务重启后需重建普通对局；模拟任务记录和锦标赛进度持久保存在 `.ui-runtime/browser.sqlite3`。赛事重启后暂停，已完成赛果保留，未完成场次从场初重开。每房间保留最近 1500 个事件，过旧的订阅会自动重新拉取快照；12 小时无访问的房间清理。AI 推进失败会暂停并记录错误，房主可单步重试或接管角色。暂停影响后续 AI 步骤，已经提交的原子动作会完成。

面向本地与可信局域网，无公网账号。角色编辑、备份恢复和训练仅允许本机及管理白名单访问。首次启动默认包含 `192.168.1.6`，之后可在角色管理的“访问白名单”页增删 IP 或 CIDR 网段；输入 `*.*.*.*` 会允许所有 IPv4 和 IPv6 来源，也会接受缺少客户端 IP 的 TCP 隧道连接，仅建议临时调试，完成后应删除该通配符。配置保存在 `.ui-runtime/management-allowlist.json`，重启后继续生效。只有将本机前置代理加入 `AUTOCOMBAT_TRUSTED_PROXIES`，服务才信任该代理传递的 `X-Forwarded-For`；检测到来自代理/隧道但没有可靠客户端 IP 时，未启用全地址通配符则拒绝访问管理接口。锦标赛对所有已建立 WebUI 会话共享，参与者可查看、创建和推进赛事；同一赛事同时只允许一个推进操作。角色管理的“保存”会修改 `characters_data.py`；新对局使用更新后的数据，已有对局和任务使用固定的数据与权重版本。小屏按纵向面板排列，矩阵和赛图可在各自面板内横向滚动。

原海豹骰对局仍走原接口；UI 房间禁止绕过会话调用旧战斗接口。新增适配层位于 `ui_server.py`；WebUI TCP 转发器位于 `ui_tcp_tunnel.py`。服务端修改源文件后运行 `merge_backend.py`，不要只编辑生成的集成后端。分发 UI 时需要同时携带适配层、TCP 转发器、模拟 worker、模拟相关源文件和 `frontend/dist/`。

## 统一数据与角色管理

`characters_data.py` 是唯一数据源，PvP 文件及训练脚本仅保留兼容入口。当前启用角色保持不变；未启用定义不会被自动启用。编辑器按属性—值展示角色、技能和效果，支持增删改、模板管理与下拉选项。点击“保存”先验证、备份，再原子替换源文件；外部修改会触发版本冲突，需重新读取。

角色管理读取全部完整定义，包括 Y13–Y17。左侧分为“已启用”和默认折叠的“已禁用”，禁用角色仍可展开、编辑和重新启用。编辑区的“启用此角色”开关通过“保存”生效；禁用只移出 `ALL_CHARACTERS`，保留角色定义，删除角色须使用独立的删除按钮。至少保留一名启用角色，新建角色默认启用。重新启用复用原定义，不会生成重复角色。

每个技能效果都有独立的“启用此效果”开关。禁用后点击保存，该效果的完整字典会留在原技能的 `effects` 列表位置，每行加 `#` 注释，并使用 `autocombat:disabled-effect` 起止标记以便恢复。Python 导入、战斗和新训练均不会执行该效果；管理页仍显示它，允许修改、重新启用或明确删除。多行效果会整段注释，重新启用会恢复原顺序。全部效果禁用时该技能的效果列表为空，技能本身仍保留。沿用自动备份、版本冲突检测和恢复工具；恢复备份也会恢复效果启用状态。分发时需同时携带 `ui_effects.py`。

角色技能具有持久的 `skill_id`（全局唯一）和 `skill_index`（固定战斗编号），管理页只读显示。禁用、重新启用、改名或调整顺序都不改变编号；例如禁用技能 2 后，技能 3 仍使用 `.s3`。完整技能注释也保留这两个字段。新技能在保存时自动分配唯一 ID 和新编号，删除不会把编号让给另一技能，避免旧 AI 策略、冷却和角色专属逻辑误指向其他技能。`next_skill_index` 保存分配进度；当前每名角色支持固定编号 1–30，禁用和删除不回收编号。不要手工修改身份字段；保存接口会拒绝重复或篡改。分发源码时还需携带 `skill_identity.py`；集成后端由 `merge_backend.py` 内联此模块。

禁用角色不会出现在新的编队、模拟、赛事及训练中，引用它们的预设会标记不可用；默认模拟和赛事仅采用有效预设。已有对局、赛事和任务继续使用固定快照。启停状态保存后标记需要重新训练；默认训练包含 3 对 3 抽样，至少需要六名启用角色。原有禁用定义若引用未定义模板（例如 Y17），可先编辑保存，启用前须修正；页面会显示缺失引用提示。

每次新训练读取当前启用名单，浏览器任务固定并校验该名单，命令行及兼容入口同样生效。召唤物训练名单从启用角色的技能生成；没有可用召唤物时跳过独立召唤物训练。重训仅替换参与训练的角色表和召唤物表，禁用角色及未参训召唤物已有的表原样保留；重新启用后才会参与下一次重训。训练页、日志及权重文件的 `params` 会列出本次训练和保留的名单。旧单表权重格式同样保留未参训条目。

“全局设置”保留基础版的 `GLOBAL_RANGE_OVERRIDE=1`，即攻击射程覆盖为 99。可显式关闭；领域半径不受此开关影响。效果类型、明确射程、随机目标和持续骰式会完整保留，列出技能时不会掷持续骰。

备份位于 `.ui-runtime/backups/`，可手动创建、下载和恢复。保存、恢复、权重替换前自动备份；恢复前校验清单。角色删除后，引用它的预设会显示失效。重新训练使用默认 50 代 × 每代 100 场及召唤训练配置，在隔离子进程执行，成功后替换 `ai_weights.json`，失败保留旧权重。

## 自动反应与 mode2 操作

战场常驻两个独立控件：“开启自动反应”“停止自动反应”。选择自己控制的单位、反应方式和次数后开启，界面实时显示剩余次数。非本人回合也可停止；当前单次结算完成，后续反应转手动，不撤销或重复结算。无可用的预设方式时停止并提示。关闭不受普通战斗按钮忙碌和战况版本变化限制，刷新不会重新开启。

控制角色不会自动控制召唤物；召唤物默认 AI，可在房间面板独立接管整组。控制权依附稳定召唤组，不因代表更换重置。

“mode2 操作与战斗管理”提供自定义技能值、伤害骰、奖惩骰、攻击次数、贯穿、致死、随机目标、公布时机、变身、持续效果结束、物品使用／转交、战斗检查点、属性调整及 AI 策略。房间分配同时用于代理操控。海豹骰可用 `.e stop [角色编号]` 或 `.e 停止 [角色编号]` 清除预设；`.sN end` 结束该技能的持续效果。

战斗记录直接呈现完整行动与检定细节，按回合、角色、技能及反应展开，保留缩进和结果，不再截成三行摘要。

## 模拟与锦标赛

模拟页支持 single、verbose、table、prelim；种子留空为随机，赛季状态留空使用“设置”中的配置。矩阵支持预设或自选小队。可取消模拟，下载 CSV／JSON；输出位于各任务独立目录，不覆盖 CLI 报告。

锦标赛每个实例只属于一种赛制。常规赛按原积分／超时／排序规则更新排名，结束后生成赛图并在附加赛前自动暂停。季后赛支持模拟本轮、本系列赛、本场、逐回合本场、进场观战、逐回合季后赛及快速模拟全部季后赛。本轮仅推进所选赛制、所选阶段；本系列赛和本场不影响其他系列赛。逐回合播放可暂停／继续。

赛图下方从上到下为“逐回合血量变化”和“逐回合战斗记录”。血量变化直接复用 ai_battle 的回合初显示，包含原有的召唤物血量汇总规则。普通模拟不传输逐步战斗记录，单场完成后一次性提供完整血量回放；逐回合模拟动态更新两栏。回放按场次保存，可从场次列表重新查看，逐回合模拟的详细记录也会保留。升级前已经完成且未记录回放的场次不在回放列表中。

进场观战使用当前棋盘，允许接管，结果只回写一次并标记人工参与；反复进入仍是同一场。暂停观战后可返回同一棋盘继续，不能同时启动另一份比赛。附加赛及各阶段淘汰赛 BoN 可在设置中修改；随机种子、源数据、权重、规则和队表均固定在创建时。

锦标赛战后按钮为“下一场”：系列赛未结束时继续当前系列赛；结束后进入赛图顺序中下一组可进行的系列赛。重复点击返回同一个后继房间。全部系列赛结束后按钮停用；普通演习仍保留“再来一场”。

分发需携带全部 `ui_*.py`、`combat_defaults.py`、`combat_settings.py`、原引擎及模拟源文件、统一数据／权重与 `frontend/dist/`。修改服务源代码后重新执行 `python start_ui.py`。

## 指定角色重新训练

在“角色管理 → 备份与训练”中勾选一个或多个已启用角色，点击“重训所选角色”。至少需要启用 6 名角色；修改角色后需先保存。所有所选角色在同一个任务中轮换参战，场次总量与全量训练相同，不随人数增加。

指定训练从零重建所选角色的单人、团队策略，以及关联召唤物策略；共享召唤物只训练一次，其策略更新也会影响其他使用者。未选角色可以作为陪练，权重保持原值。网页复用隔离任务、日志和安装前自动备份；失败时不会替换原权重。完成后保留全局待训练标记，需要覆盖全部修改时使用“重新训练全部启用角色”。

命令行在项目目录执行：

```powershell
python ai_trainer.py --characters Y2 Y6 Y8
python ai_trainer.py --character Y2
python ai_trainer.py
```

编号必须属于当前已启用名单；前两种参数互斥，重复编号自动去重。不传参数时继续训练全部启用角色。命令行直接原子替换项目权重，执行前可自行保留备份；网页会自动备份。海豹 `.train` 仍执行全量训练。

## 设置

侧栏“设置”和顶部个人信息入口均进入同一页面。个人偏好只保存在当前浏览器；服务器设置、队伍表、全局射程和访问白名单需要本机或管理白名单设备访问。

AI 战斗原有配置、正文中的可调参数和完整队伍表已集中提取。页面提供显示等级、日志、各阶段延迟、赛季状态、循环轮数、目标场数、地图、并发数、回合限制、抽签权重矩阵及 BoN 编辑。2v2／3v3 队伍可增删、修改成员和排序；3v3 保留二人和四人特殊阵容。禁用角色所在队伍保留但不能用于新任务；未知或重复角色不能保存。

WebUI 配置中的地图边长支持 8–16，允许长宽不同；命令行显式地图参数继续遵循引擎自身的支持范围。

“锦标赛逐回合基础等待”按当前播放倍率缩放，可设为零。保存后从下一次事件等待起生效；已经开始的等待不追溯调整。日志等级作用于后续记录。赛事规则和队伍表只用于新任务，运行中及恢复后的赛事继续使用创建时的快照。模拟的快速运行模式会明确关闭展示等待；详细单场与赛事逐回合播放使用各自设置。

配置默认值只定义在 `combat_defaults.py`，运行参数由 `combat_settings.py` 读取；`team_tables.py` 保留导入兼容入口。默认实例保存到 `.ui-runtime/settings.json`，其他实例保存到 `.ui-runtime/settings-端口.json`。独立运行 AI／模拟默认读取默认实例；设置环境变量 `AUTOCOMBAT_UI_INSTANCE` 可选择其他实例。显式命令行参数优先。端口、监听地址和输出文件路径在页面只读；停用的 1v1 随机加赛字段只读，自定义战斗延迟兼容旧名 `CUSTOM_BATTLE_DELAY`。

服务器保存支持版本冲突检查、类型与范围校验、原子替换和保存前备份。设置加入备份恢复；任务目录中的 `settings-snapshot.json` 记录创建时的配置。恢复旧版备份时，也会迁移原 Python 队伍表。分组恢复默认值需保存后生效，离开页面或刷新会提示未保存修改。

配置逐项清单与核对结果见 [配置提取与验证](../archive/artifacts/settings/配置提取与验证.md)。

## 帮助与角色资料

侧栏底部“帮助”打开机制说明及角色卡文字索引。机制说明直接使用 [游戏总机制](../docs/游戏总机制.md)，前端构建时载入，无需同步复制。角色卡悬停满一秒显示概览，点击概览打开详情；自由对战卡片本身仍用于编队，右上角 `i` 可单独打开详情。

详情中，已在当前角色卡内说明的技能、特性、专属名词及其简称，在名词与定义能同屏显示且中间没有隔着完整技能时保持普通文字；隔着至少一个完整技能，或定义因滚动、窗口尺寸、折叠而不可同屏查看时，仍显示蓝字链接与悬浮释义。名词自身的技能、特性或定义段落中始终不生成自指链接，此规则优先于距离、同屏与折叠状态。其余蓝字名词可悬停查看简释，或点击在角色卡内展开完整定义和相关规则。概览本身不生成名词链接。角色管理页支持 Ctrl+S（亦支持 Command+S），使用与保存按钮相同的校验和备份流程；白名单标签页保存白名单。

页面地址采用 `/ui/home`、`/ui/library`、`/ui/tournament` 等路径，支持刷新、前进后退及 `?character=Y1` 角色详情链接。旧 `/ui/?room=...` 邀请链接继续可用；打开其他页面时，后台恢复房间不会强制跳转。

验证：`npm test` 与 `npm run build`。交互回归使用 `npm run test:browser`，默认连接 `http://127.0.0.1:8890` 的已构建页面及本机 Edge；可设置 `UI_BASE_URL`、`UI_BROWSER_CHANNEL`，以及截图目录 `UI_TEST_ARTIFACTS`。测试中的角色保存、白名单和赛事请求均被拦截，不写入真实数据。
# 剧情模式

首页／侧栏“剧情模式”进入章节列表；“创作工作区”可打开服务端目录，默认是仓库内 `story-projects/demo/`。源码与流程图联动，Ctrl+S 保存，预览使用独立进度，发布固定不可变版本。

`npm run build` 同时构建主界面与独立 WebGAL 播放器。首次构建会安装播放器依赖。`npm test` 包含既有单测与剧情核心单测；`npm run test:story:coverage` 输出剧情核心覆盖率。浏览器测试使用独立服务并设置 `UI_BASE_URL`。

完整语法、权限及连续战斗见 [STORY_AUTHORING.md](../docs/STORY_AUTHORING.md)。
